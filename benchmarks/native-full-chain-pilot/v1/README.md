# Native full-chain pilot, version 1

Two exploratory application pairs use fresh native Codex desktop chats, the same user account and `gpt-6-luna` with high effort. No CLI generation, forked planning history, additional agents or application repairs by the evaluator. Each pair receives byte-identical prompts and specifications. No prompt asks for Zero, GitHub search or component reuse.

The baseline A disables the RepositoryZero plugin and standalone MCP server. B enables the installed 0.8.0 skill and scoped MCP execution bridge, including real Jev selection, pinned source preparation and component verification through the existing API/PostgreSQL/Graphile worker. This compares the complete enabled assistance bundle against A; it does not isolate Jev's marginal contribution or MCP transport alone. Connection smoke tests remain separate from application runs.

The two tasks are:

- [Inventory Import](../../native-inventory-pilot/v1/SPEC.md), using its unchanged [common prompt](../../native-inventory-pilot/v1/prompt.txt) and qualified [independent grader](../../../platform/scripts/native-inventory-pilot-grader.mjs): upload, strict CSV validation, preview, atomic SQLite import, idempotency, restart and desktop/mobile keyboard workflows.
- [StockDesk](../../native-stockdesk-pilot/v1/SPEC.md), using its [common prompt](../../native-stockdesk-pilot/v1/prompt.txt) and [independent grader](../../../platform/scripts/native-stockdesk-pilot-grader.mjs): two warehouses, products, adjustments, atomic transfers, globally idempotent references, immutable movement history, concurrent stock protection, virtual CSV validation, atomic batch commits, filters and export. The native specification adds a generic parser boundary and explicit 16,384-byte/128-record CSV bounds to the preserved historical StockDesk task.

Each coding turn has a requested maximum of twenty minutes and 100 MiB of new application files/dependencies/test data. A host deadline is observed rather than claimed as a Zero-enforced host-wide cap. No evaluator intervention or grader feedback enters an unfinished pair. Failed, incomplete, unused and no-fit outcomes are retained. Missing history/model/identity or a shared infrastructure failure invalidates comparability and is reported separately; it does not become an application failure or zero cost.

Before generation a private immutable manifest records source HEAD and file hashes; prompts/specifications/starters/graders; installed plugin bundles and activation files; project configurations and operator binding/policy digests; native app/core, model/effort and runtime; preflight transcripts; remaining cumulative API authorization; execution order and warm-cache limitations. The first pair's order is randomly selected once; the second uses the reverse order. Runs are sequential. Before the second task, complete prior workspaces and Git history are archived outside both coding roots and replaced with fresh neutral starters; the same paths/configurations are retained. No runtime, prompt, source module, grader or plugin change is made inside this two-task epoch.

Independent acceptance is identical for A/B. Whole applications must pass API/data/persistence and desktop/mobile keyboard checks. Component conformance, actual observed application calls, source hashes and Zero receipts are separate evidence. Functional and browser failures remain visible even if the model reports success. A failed application cannot win on speed or tokens. Review source and screenshots with a common rubric for transaction boundaries, validation, safe text rendering, error handling, maintainability and usability; visible dependency choices prevent a claim of fully blinded review.

Record native coding duration and counters, independent grading time and complete measured workflow separately. Host total input already includes cached input; reasoning is a subset of output. Preserve cache read/write and uncached counts without double counting. Shared host/provider caches and other account activity are uncontrolled, so there is no cold-cache or causal cache claim. Subscription invoice cost is unknown. All new Jev calls share the separately authorized cumulative USD 3 allocation, including setup qualification; the held historical USD 1 is untouched. Report actual provider usage separately from conservative holds and development/setup costs separately from trial costs.

The StockDesk base grader controls passed 18/18 without skips. Native extension controls passed 5/5: boundary fixtures, a positive reference, and deliberate missing byte-limit, missing row-limit and component-bypass faults. A combined reference passed API, SQLite restart, browser, all eight extension checks and unchanged-source verification. Its first combined attempt exposed a synthetic fixture that returned HTTP 500 for malformed CSV instead of the specified 400; the original failure was retained and only that reference fixture was repaired before generation. These are development controls, not a hidden holdout or model application results.

Two tasks and one pair per task can reveal useful failures and observed tradeoffs; they cannot establish repeated benefit, universal value, G2 acceptance or a complete MVP. No predetermined percentage improvement is assumed.
