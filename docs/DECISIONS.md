## A17: išmatuotas ribotas PDF profilis

Pirmam MVP pasirenkamas [pdfplumber profilis](../platform/packages/adapters/pdfplumber/profile.json), atskirai užfiksuotas po Docling bandymo: pdfplumber 0.11.10, source commit ir aštuonių wheels versijos/hash, Linux amd64 ir pinned Python image. Tai Python parserio priklausomybė esamame izoliuotame worker kelyje, ne naujas Python produkto branduolys ar scheduler. Profilis neturi ML modelių ar OCR; palaiko tik born-digital stačiakampes lenteles su aiškiomis ruled-cell ribomis, be sujungtų ar trūkstamų langelių geometrijos ir be text-strategy fallback. Pradinės ribos lieka ≤1 MiB įvestis, ≤5 puslapiai, ≤1 MiB išvestis, 30 s, 512 MiB RAM ir išjungtas tinklas.

[Docling matavimas](../platform/packages/adapters/docling/spike-results-2026-10-17.json) rodo 2 133 152 856 B image ir 384 434 788 B modelių: 2 517 587 644 B vien PDF image/modeliams prieš Zero/browser/coding, daugiau nei visas 2 000 000 000 B G0 limitas. Visi dešimt konvertavimų ir atskiras warm repeat nutrūko pipeline paruošime su `ModuleNotFoundError`; tai neužbaigta konversija, ne Docling ekstrakcijos kokybės įvertinimas. Tikslus trūkstamas modulis tuo bandymu neužfiksuotas; OpenCV priežastis lieka statinio source tyrimo išvada, ne stebėtas exception vardas. Docling nepridedamas į privalomą MVP bazę; grįžimas prie jo reikalauja atskiro profilio, pamatuoto closure ir naujo sprendimo.

[Light profilio matavimas](../platform/packages/adapters/pdfplumber/spike-results-2026-10-17.json) fiksuoja 310 032 256 B image, nulį modelių ir 356 908 499 B konservatyvų retained upper bound; 10/10 sintetinių fixtures bei 56 skaitiniai langeliai atitiko tą patį užšaldytą nepriklausomą grader su page/bbox provenance. Docling paruošimo nesėkmės nėra modelių kokybės palyginimas. [Vėlesnis autentifikuotas API/Graphile kelias](experiments/SCOPED-FILE-COMPONENTS-2026-10-17.md) turi atskirą epochą. Šie įrodymai nesuteikia OCR, arbitrary PDF, nepriklausomo holdout ar G2 kokybės teiginio. P2.2 išlaiko struktūrinio JSON/CSV, PDF ArtifactRef, puslapių provenance ir numerinio validator reikalavimus; [Dabartinis parserio runner](../platform/packages/adapters/pdfplumber/runner.py) išveda JSON lenteles; atskiras CSV eksportas ir produkto formatų peržiūros šiais bandymais nepriimti. Formatų pateikimo ir produkto srauto vartai lieka kvalifikuotini. Paruošimo peak diskas, daemon-side cancellation, transityvinių licencijų platinimo peržiūra ir visas aktyvaus produkto G0/G1 lieka atviri.

## A18: vienas MCP įgyvendinimas, atskira protokolo kvalifikacija

Pirmas vietinis MCP serveris ir klientas lieka esamame Rakazo `@rakazo/adapters` pakete su oficialiu `@modelcontextprotocol/sdk`, šio sprendimo source baseline tiksliai 1.30.0 [package manifeste](../platform/packages/adapters/package.json) ir [lockfile](../platform/pnpm-lock.yaml). Pirmas transportas — STDIO, pirmas execution profilis — Linux x86_64/WSL pagal [MCP kontraktą](MCP-INTEGRATION.md). Atskiras Python MCP SDK/v2 API adapteris nėra pirmo MVP priklausomybė; PDF parserio Python runtime šio pasirinkimo nekeičia. Nauji pin ar API pakeitimai eina per esamą upstream/conformance kontrolę, o ne per neversijuotus FastMCP pavyzdžius.

[Realus STDIO protokolo testas](../platform/packages/adapters/src/zero-mcp-stdio.test.ts) ir [serverio testai](../platform/packages/adapters/src/zero-mcp-server.test.ts) yra riboti konkretaus įgyvendinimo įrodymai. SDK 1.30.0, Zero serverio semver, tool schema ir negotiated MCP protocol version yra skirtingi faktai; dabartinių testų `2025-11-25` nėra leidimas teigti visų MCP funkcijų conformance. P2.5 reikalauja tikros palaikomo transporto ir host poros initialize/capabilities, schemų, ribotų tool atsakymų, klaidų, cancellation/reconnect ir versijų patikrų. Host roots, kai palaikomi, kertami su operatoriaus suteikta apimtimi; kitu atveju būtinas aiškus konfigūruotas root. Roots nėra OS sandbox ar grant. Operator binding, principal/scope ir auth/revoke/permissions patikros lieka privalomos; host modelio auth neeksportuojamas. Būsimo HTTP/OAuth profilio TLS, Origin/Host, token audience ir tenant/project ACL kvalifikuojami atskirai; STDIO ar TypeScript export testas jų neuždaro. Kiekvienas native host/OS, plugin lifecycle ir tikras naudingas rezultatas išlaiko atskirus priėmimus.

A17–A18 keičia provider/SDK pasirinkimą, ne priėmimo slenksčius. P0.8, P2.2 ir P2.5 checkboxai šiuo ADR neuždaromi; G0 2 000 000 000 B viso profilio riba, G1 ir G2, originalūs fixtures/grader, visos nesėkmės ir užšaldytų cohort ribos nesikeičia.

[MCP kontraktas, support matrica ir profilių vartai](MCP-INTEGRATION.md), [native Codex bandymas](NATIVE-CODEX-BENCHMARK.md). Viena deterministic vertikalė leidžia pilotą prieš pilną trijų modulių MVP; ji neatšaukia Jev, Library ar G0/G1/G2 reikalavimų.

Ankstesni ADR01–ADR42 su visa argumentų istorija išsaugoti [karantine](quarantine/README.md). ADR39 Codex pasirinkimą pakeitė Claude prenumerata; ADR41 Sonnet ir ADR42 „cloud neturi CLI“ apibūdina senus bandymus, o ne dabartinę aplinką. Naujausi StockDesk eksperimentai naudojo Haiku 5.5/high, bet nėra šiuo metu vykdomo bandymo.

Nekeičiami principai: vienas autoritetingas scheduler; grants ir effect/recovery kontrolė; licencijų/source/model/data atskyrimas; provider-neutral ribos; apibrėžtas hostile lane, atskirtas nuo trusted local Docker; opt-in shared evidence ir atskiras trusted release kelias. Šis auditas jų nepašalina.
