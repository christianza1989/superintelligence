ADR34: naudotojui leidus pradėti MVP, realiam įgyvendinimui pasirinkta Rakazo exact-pin adaptacija `platform/`, React ir bendri UI tokens, esamas Graphile/PostgreSQL backend bei Astro svetainė. UI build/test pjūvis veikia; pilni P0/P1 kokybės vartai nelieka automatiškai priimti. [Faktai ir blokai](IMPLEMENTATION.md).

ADR35: po naudotojo patikslinimo abu agentai patvirtino metadata katalogą ir tikslinį source gavimą pagal poreikį. Katalogas nėra visų repo kopijų ar vieno didžiulio sujungto executable archyvas. Core → index/shortlist → pinned source/package/API → izoliuotas projekto build/test; tikslus patvirtinimo scope, baigtinis cache, version lock ir naujos upstream versijos atskira patikra. [Veikimo paaiškinimas](PROJECT-CREATION.md#0-katalogas-nėra-visų-repo-atsisiuntimas). Vietinė paieška įgyvendinta; pilnas fetch/build ciklas dar NOT_RUN.

ADR36: Jev pritaikymas išplečiamas nuo tools selector į ribotų repo, dokumentų fragmentų, failų/testų ir coding triage sprendimų auditą. Tai struktūrizuoto pasirinkimo role po deterministinio retrieval, ne naujas scheduler ar pagrindinio coding modelio pakeitimas. Reuse vertinimas apima jau Rakazo esantį Jev auto-review ir bendrą bounded response reader. [Pritaikymas, atskiras retrieval-only baseline ir visos užduoties sąnaudų matavimas](JEV-APPLICATIONS.md); sutaupymo procentai/live API dar neįrodyti, viešo masinio intake paid cap0 išlieka.

ADR37: naudotojų užduotys gali generuoti vietinius konkrečios versijos kokybės įrodymus, o opt-in nuasmeninti faktai — padėti bendram patikimam vertinimui. Agentų įvertinimai/naudojimas/priimti PR nepakeičia verified profilio vartų; klaidos ir unknown išlieka. Indėlis keliauja į originalų upstream arba RepositoryZero adapterį pagal problemos vietą. [Bendruomenės kokybė](COMMUNITY-QUALITY.md); platesnė runtime infrastruktūra dar neįgyvendinta.

ADR38: sistemos PR turi oficialią RepositoryZero kilmę ir agento rolę; publikavimas per vieną patikimą jungtį su tikra GitHub tapatybe bei suteiktu scope. Agentų AI pobūdis aiškus, upstream autorystė išlaikoma. [Tapatybės ir publisher specifikacija](AGENT-IDENTITY.md); app/account dar nekonfigūruotas, išorinių PR neatlikta.

ADR39: pirmas coding modelis ir porinis bandymas naudoja naudotojo Codex CLI OAuth, pageidaujamą tą patį `gpt-6.1-sol`/`xhigh`. OpenRouter raktas skirtas Jev repo atrankos jungčiai; auth/model/entitlement patvirtinami gyvu conformance, ne vien rakto buvimu. CLI OAuth neeksportuojamas iš credential failų. Pradinių probe startup blokas vietinis read-only CLI state, OpenRouter preflight tinklas taip pat blocked; nei modelio invoke, nei lenktynių PASS nėra.

ADR40: daugkartinis [Zero Lab](ZERO-LAB.md) modulis pernaudoja esamą eval/testkit kodą. Versijuoti prompt/router/retrieval/model/agent/cache profiliai, nekintamas acceptance ir atskiras validavimo rinkinys leidžia kartoti kokybės/laiko/sąnaudų kalibravimo ciklą. Offline plano sudarymas veikia; CLI runner ir palyginimas vėliau įgyvendinti, viena Claude pora patikrinta pagal ADR41; Lab UI vis dar planuojamas.


ADR41: dabartiniam kalibravimui naudotojas pasirinko oficialų Claude CLI su prenumerata, Sonnet5.5/high. Codex auth ir OpenRouter lenktynės atidėtos. Importuota v2 pora tikrina statinį Zero katalogo kontekstą, ne pilną produkto runtime. Graderio WAL false-negative pataisytas nekeičiančia originalaus tūrio kopija; promptas v2 iš anksto paaiškina tikslų accessible heading kontraktą. Abi programos pakartotinai patikrintos, o25% bendro AI pranašumo teiginys atmestas dėl vienos poros ir graderio laiko variacijos. [Rezultatai ir kilmė](CLAUDE-CALIBRATION.md).

ADR42: tolesnis kalibravimas vykdomas ribotomis kohortomis po1–3poras. Pirmas režimas tikrina baseline/legacy Zero pakartojamumą; atskiras compact režimas vertina naują formatą ir trumpesnį kandidatų rinkinį nepakeisdamas seno profilio. Source/prompt/profile pokyčiai nutraukia kohortą; coding/grading laikai atskiri, failures ir unknown išlaikomi.54offline regresijos ir dry-run patikrinti; nauja gyva kokybės/tokenų nauda NOT_RUN, nes cloud nėra Claude CLI.
