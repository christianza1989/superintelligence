# Scoped file components: bounded development proof

2026-10-17. These results qualify the stated development paths, not G2, independent holdout, repeated benefit, or the complete MVP.

PDF and browser jobs now use the existing authenticated API, PostgreSQL artifacts and Graphile worker. Each submit accepts only `fileId`, `idempotencyKey` and `deadline`. Current operator grants allow at most ten relative file paths with expected SHA-256 values. Paths have at most twelve components including the filename (eleven directories), validated by both the grant schema and capture consumer before reserving private staging. The snapshotter copies one bounded file into private staging before an owned immutable input artifact is persisted. Worker dispatch reads that artifact, never a caller path or a live project file.

Metadata ownership, file ID, SHA, current membership, grant and profile are checked before private input reads. Dispatch and successful publication recheck finite database time, deadline, expiry and cancellation. The request-row lock selects one terminal receipt. CSV names and nonces remain compatible; CSV, PDF and browser share four outstanding jobs per scope. Artifact transport returns hash-checked JSON in pages of at most 16 KiB.

The nine integration controls cover real-session and foreign-scope/origin denial, actual PDF and arbitrary allowlisted HTML extraction, idempotency, bounded artifact pages, prohibited caller arguments, cancellation before worker reconnect, file-grant revocation before private request reads, immutable PDF input after a host edit, grant revocation after successful storage, and the quota shared with CSV. They dispatch no model calls.

The initial integration attempt passed two controls and failed seven submit-dependent controls before dispatch. A distinct diagnostic found that the new capture consumer omitted the snapshotter's `files/` directory. The consumer was corrected without relaxing permissions, authorization or limits; the full nine controls then passed. A separate diagnostic used a stale ephemeral test port and failed before suite setup. Private original reports and logs remain retained.

Immutable inputs and receipts remain retained for operator-managed retention. Four bounded transient snapshot slots limit simultaneous capture; crash orphans require explicit operator recovery. This proof adds no automatic TTL, public upload, host-file freshness assertion, or generalized browser execution permission.

A further read-boundary review reproduced twelve revocation failures across the three families: authorization removed during a request body, receipt body, receipt metadata or queue-state read still allowed data to return. Shared readers now reauthorize the current caller after those awaited reads. The original-source regression passed 20 and failed all twelve new controls; after the fix all 32 passed. The combined reader/MCP/transport suite passed 149/149. These are deterministic read-race controls, separate from the earlier nine real API/worker cases.

Review reproduced a cleanup failure in the original backend commit for a valid fifteen-directory allowlist path: capture persisted the input before cleanup exceeded its depth limit, and the orphan then blocked fresh captures. The explicit path-component limit prevents this before reservation. Cleanup's depth, entry, byte and slot bounds remain unchanged. The filesystem regression checks rejection before persistence, capture at the accepted depth boundary, then another capture with no leftover slot. A retained RED run against the original source passed 36 and failed two input/policy controls; the same suite against the bounded-path fix passed all 38.
