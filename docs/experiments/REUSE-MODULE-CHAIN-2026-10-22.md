# Jev-selected source modules — development qualification

Updated 2026-10-22. This epoch extends the existing API/PostgreSQL/Graphile worker with focused source-module preparation and verification. It does not replace the scheduler or move the host's coding conversation into Zero. Native application comparisons remain separate from these controlled checks.

## Library and selection

The [module registry](../../platform/packages/core/src/zero-reuse-modules.data.json) adds three file-level alternatives: d3-dsv 3.0.1 (ISC), Papa Parse 5.5.3 (MIT), and fflate 0.8.2 (MIT). Original selected distribution files and licenses are retained in [reuse-sources](../../platform/packages/adapters/reuse-sources). Metadata records the exact npm release, tarball integrity, upstream gitHead and selected-file SHA-256. Distribution integrity is distinct from an independently reproduced upstream build. The historical 796-entry repository catalog and lockfile are unchanged.

Discovery returns candidates within a broader application request; it does not certify all task constraints. The host decomposes the application into focused needs. The authorized Jev selector sees only eligible operator-allowlisted alternatives, their source facts and constraints. Unsupported streaming, larger explicit byte requirements, or archive extraction/encryption are rejected before paid selection. Remaining unknown requirements are not certified by keyword matching.

Prepared CSV adapters are synchronous and bounded to 16,384 UTF-8 bytes, 512 rows, 64 columns and 4,096 characters per cell. They support BOM, quoted commas, escaped quotes and multiline fields with strict quoting and rectangular rows. The ZIP creation adapter supports at most 32 root-level files, 131,072 input bytes and 196,608 archive bytes; it does not extract archives. Business logic and database integration remain application work.

## Execution and evidence

Source MCP 0.8.0 / schema 1.8.0 adds `zero_reuse`, `zero_reuse_job`, `zero_reuse_artifact` and `zero_reuse_verify` to the optional scoped execution profile. Default discovery remains three tools. Preparation uses the existing stored Jev connection, trusted payer mapping and finite routing allocation. The model supplies neither credentials nor filesystem roots. The immutable receipt contains the selected module's exact files, hashes, licenses and approved relative integration entrypoint.

The host reviews and integrates those files. Verification loads the same-scope preparation, checks source pins, snapshots the approved files and runs the existing isolated Docker path. It observes actual vendor function inputs and outputs and checks conformance with an independent oracle. A file saved or imported without a vendor call is insufficient. Verification dispatches no additional Jev call.

On the current Linux development profile, eleven actual MCP → HTTP/authenticated API → PostgreSQL → Graphile → Docker controls passed with an injected offline provider:

- Scoped backend status and natural application capability recall.
- Separate d3-dsv, Papa Parse and fflate preparation, host fixture integration and actual-use verification.
- Correct custom parser without vendor use rejected; changed pinned source rejected before Docker.
- Unsupported constraint abstains without dispatch; provider abstention is preserved.
- Unknown preparation is blocked; revoked grant blocks new work.

These controls were repeated after a WSL interruption and all eleven passed again. Paid provider calls were zero in both controlled runs. The failure before them exposed a signed-request field-order mismatch after schema parsing; its original HTTP 403 and diagnostic are retained, and a PostgreSQL submit/reload regression was added. A separate regression batch interrupted by the environment is incomplete, not a passing result.

Earlier development failures are preserved: package-store mismatch and interrupted workspace dependency resolution (no manifest/lockfile change), trailing-row/parser-trace discrepancies, ZIP trace serialization, test snapshot cleanup and MCP output-schema mismatch. Repairs were followed by 147 focused offline regressions passing. Budget helper tests passed 12/12, including a separate USD 3 allocation which does not alter an exhausted historical allocation. Package/HTTP fixture checks passed for a built 0.8 package; they do not prove a native host connection.

The subsequent PostgreSQL worker regression suite passed 15/15 without skips, including module request integrity across submit/reload and single dispatch on replay. Two initial attempts used an obsolete ephemeral port after restarting the owned PostgreSQL container and failed during setup; those reports are retained. The runner now resolves the actual loopback mapping after each start. Adapter and API TypeScript checks both passed.

The first live-profile preparation attempt abstained before dispatch: its phrase “no streaming” was incorrectly treated as a streaming requirement. The failure is retained with zero provider calls. Eligibility now distinguishes explicit exclusions of known unsupported capabilities while retaining separate positive or ambiguous requirements; the original goal still reaches Jev unchanged. Nine module regressions passed after this repair, including conflicting positive requirements and byte caps.

## Limits and next gate

The selected Node Docker profile is read-only, network-disabled and bounded to 128 MiB, one CPU and ten seconds. Evidence concerns the component snapshot and exercised calls. It is not hostile-code isolation, a whole-application verdict, a hidden holdout, or proof of benefit. Later edits require a new verification. Packaging these worker-side source assets into a relocated runtime is a separate qualification.

The newly authorized live API allocation is capped at USD 3 for integration and both application tasks. It is separate from the fully held historical USD 1 allocation. Reservations are retained across fixture/database restarts; unknown costs are not refunded. Native host subscription usage and its cache counters remain separate from provider cost. A real Jev run, fresh native connection preflight and identical-prompt application comparisons are still pending at this checkpoint. No MVP or repeated-benefit gate is closed here.
